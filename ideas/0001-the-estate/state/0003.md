# State 0003

## Established

T asked whether `research` should drop Findings into `reference/` as OKF
documents. Answered and sealed as **ADR 0018**: Findings *speak* OKF but
*live* in the record — the artifact extends record frontmatter with the OKF
families (`sources:` with credibility signals as the citations, per-claim
footnotes, actor-convention `generated:`, honest `stale_after:`), stays in
`artifacts/` where the machinery consumes it, and a finding with
cross-record value is **promoted** to `reference/` by operator selection,
citing the artifact as source. Relocation was rejected: it would hide
Findings from the inputs chains and gap derivation, fork the type schema,
and muddy the reference's derived-view charter.

## Decisions

- **Findings-first is a partial answer to ADR 0017's migration question** —
  the wedge case where OKF pays most, adopted per skill contract with zero
  template changes (`type: Findings` was already conformant; OKF permits
  the record keys as extensions).
- **Promotion is operator-selected at the close, never the Factor's
  default** — otherwise every research run silently grows the bundle and
  the reference stops being curated.

## Gold nuggets

- External knowledge rots on a schedule the other types don't have; OKF
  makes the rot a timestamp comparison.
- Promotion copies knowledge out; it never moves the artifact.

## Tensions

- **Building it is more fun than using it** — still live. Three structural
  sessions in a row; the estate still holds one record.

## Open questions
