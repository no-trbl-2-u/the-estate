# State 0005

## Established

T removed the OKF frontmatter from `CLAUDE.md`, then from `AGENTS.md`, and
pointed at the OKF announcement to settle why. The blog is decisive: OKF is a
**bundle format for concepts** — directories of markdown whose file paths form
each concept's identity, cross-linked into a graph, consumed by catalogs,
search, and agents browsing the bundle. That is `reference/`, exactly.

A memory file is not a concept and has no bundle. The harness reads it by
injecting it verbatim at session start, so the frontmatter was never
conformance — it was OKF's shape applied outside the format's scope, costing
tokens every session for metadata nothing reads. Both files are now bare.
Recorded as ADR 0019 decision 4, which **amends ADR 0017 decision 3**; ADR 0017
carries a status annotation and the index a marker, its body untouched.

## Decisions

- **The exclusion is principled, not an exception.** ADR 0017 decision 4
  already excluded `.claude/skills/` and `.claude/agents/` as *operational
  configuration, not documentation*. Memory files belong in that category and
  are excluded on the same grounds — not as a special case carved out for two
  files.
- **Frontmatter follows how a document is read.** Opened → catalogued →
  frontmatter earns its keep. Injected → not catalogued → it does not.

## Gold nuggets

- The first version of ADR 0019 justified stripping `CLAUDE.md` on token cost
  and called it "the one deliberate exception to ADR 0017." That reasoning was
  true but secondary, and *exception* was the wrong word: the real fact is that
  the file was never in OKF's scope. A correct decision resting on a weak
  reason will mislead the next reader; the ADR now carries the right one.
- Adopting a format is not the same as knowing where it stops. ADR 0017
  stamped everything prose-shaped; the boundary only became visible when a
  file's *delivery mechanism* changed.
