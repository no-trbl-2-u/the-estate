# State 0002

## Established

The "OKF" reference that has ridden as an open question since ADR 0008 is
answered: it is **Google Cloud's Open Knowledge Format** (v0.2), not an
OpenAI format. T pointed at the spec; it is now vendored, and the estate's
documentation adopted it (ADR 0017):

- A root `reference/` bundle — the spec plus one OKF concept per verb (17),
  office (13), and artifact type (10), and core concepts for the law, the
  record model, scoring, lenses, shapes, playbooks, falsifiers, and the
  estate itself. Every concept's `sources` names the governing file;
  `system/` wins where they disagree.
- OKF frontmatter on all prose documentation. Historical records carry
  `status: deprecated` with bodies untouched. The falsifier documents carry
  `stale_after: 2026-09-25` — the check date is now machine-readable
  staleness.
- Conformance validated mechanically: 49 concepts, all links and source
  paths resolving, every doc parsing with a `type`.

## Decisions

- **The reference is a derived view, never a second source of truth.**
  Its provenance frontmatter is what keeps that honest.
- **Templates, skills, agents, and record data are excluded** from the
  frontmatter pass: forms, configuration, and data are not documentation.
- **The survey adopts OKF trust semantics**: `survey` stamps
  `generated: { by, at }` alongside `covers:` when it runs.

## Gold nuggets

- The falsifier's check date is an OKF `stale_after` — when the falsifiers
  concept reads as stale, the clock has run out.
- "Where they disagree, `system/` wins."

## Tensions

- **Building it is more fun than using it** — still live, and this session
  fed the machine again. The estate holds one record: its own.
