# Playbook: split

**Composition:** `explore ▸ capture ▸ capture …` — no new verb required.

When one record turns out to be carrying two (or more) ideas — a tension that
is really two different projects pulling on one name:

1. **`explore` the conflated artifact.** The Forager's variants make the
   separate ideas visible as content.
2. **`capture` each idea worth its own life** into a new record. Each child
   Spark's `inputs:` cites the parent's explore artifact — and that
   cross-record `inputs:` chain *is* the split edge, derived per ADR 0005.
   Each child's Origin names its parentage:
   `Split from idea-NNNN @ state/NNNN because …`
3. **Decide the parent's fate**: it may continue (now honestly about one
   thing), or `retire` with reason `split into idea-AAAA, idea-BBBB`.
4. The Steward closes every touched record per protocol.

Each `capture` is an explicit operator selection — a child per decision, never
a litter per command. That friction is deliberate: divergence needs no
amplifier here (`system/SCORING.md`).
